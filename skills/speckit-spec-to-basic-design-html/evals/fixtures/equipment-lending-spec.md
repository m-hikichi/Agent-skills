# Feature Specification: 備品貸出管理デモ - 予約・貸出・返却

**Feature Branch**: `020-equipment-lending-demo`

**Created**: 2026-06-01

**Status**: Draft

## 概要 / 1行サマリ

利用者が共有備品を検索・予約し、管理者が貸出・返却と在庫状況を管理できるデモ用アプリ。

## Clarifications

### Session 2026-06-02

- Q: 同一備品を同じ時間帯に複数人が予約できるか？ -> A: 在庫数を超える予約は受け付けない。
- Q: 返却期限を過ぎた場合は？ -> A: 利用者と管理者へ1日1回通知する。
- Q: 管理者以外が備品を登録できるか？ -> A: 登録・在庫調整は管理者のみ可能とする。

## User Scenarios & Testing

### User Story 1 - 備品を検索して予約する (Priority: P1)

利用者は備品名・カテゴリ・管理番号で貸出可能な備品を検索し、利用期間を指定して予約する。

**Acceptance Scenarios**:

1. **Given** 指定期間に在庫がある備品、**When** 利用者が予約する、**Then** 予約が確定して予約番号が表示される。
2. **Given** 指定期間の予約数が在庫数に達している備品、**When** 利用者が予約する、**Then** 予約は拒否され代替期間が案内される。

### User Story 2 - 貸出と返却を処理する (Priority: P1)

管理者は予約番号を確認して備品を貸し出し、返却時に状態を記録する。

**Acceptance Scenarios**:

1. **Given** 有効な予約、**When** 管理者が貸出処理を行う、**Then** 貸出日時と返却予定日が記録される。
2. **Given** 貸出中の備品、**When** 管理者が返却処理を行う、**Then** 在庫が戻り備品状態が記録される。

### User Story 3 - 備品と在庫を管理する (Priority: P2)

管理者は備品を登録し、故障や廃棄による在庫数の変更を記録する。

**Acceptance Scenarios**:

1. **Given** 新しい備品情報、**When** 管理者が登録する、**Then** 検索・予約対象として表示される。

### Edge Cases

- 予約期間の開始日時が終了日時以降の場合は入力エラーとする。
- 返却時に故障が見つかった場合は「点検中」とし、予約可能在庫から除外する。
- 貸出開始後に予約を取消すことはできない。

## Requirements

### 認証・権限

- **FR-001 (MUST)**: システムは、認証済み利用者のみに備品検索・予約機能を提供しなければならない。
- **FR-002 (MUST)**: システムは、利用者と管理者のロールを持ち、備品登録・在庫調整・貸出・返却は管理者のみに許可しなければならない。

### 備品検索

- **FR-010 (MUST)**: 利用者は、備品名・カテゴリ・管理番号の部分一致で備品を検索できなければならない。
- **FR-011 (MUST)**: 検索結果には、備品名・カテゴリ・現在の貸出可能数・次回利用可能日時を表示しなければならない。

### 予約

- **FR-020 (MUST)**: 利用者は、利用開始日時と終了日時を指定して備品を予約できなければならない。
- **FR-021 (MUST)**: システムは、指定期間に重なる予約数が利用可能在庫数を超える場合、予約を拒否しなければならない。
- **FR-022 (MUST)**: 利用者は、貸出開始前の予約を取消できなければならない。

### 貸出・返却

- **FR-023 (MUST)**: 管理者は、予約番号を確認して貸出処理を行い、貸出日時と返却予定日を記録できなければならない。
- **FR-024 (MUST)**: 管理者は、返却処理時に備品状態を「利用可能」「点検中」「故障」から選択して記録できなければならない。
- **FR-025 (MUST)**: システムは、返却期限を過ぎた貸出を検出し、利用者と管理者へ1日1回通知しなければならない。

### 備品管理

- **FR-030 (MUST)**: 管理者は、備品名・カテゴリ・管理番号・在庫数を登録および編集できなければならない。
- **FR-031 (MUST)**: 管理者は、在庫数を変更する際に変更理由を記録しなければならない。

### データ出力【v1対象外・将来】

- **FR-040 (SHOULD)**: 【v1対象外・将来】管理者は、月次の利用実績をCSV形式で出力できるべきである。

### Key Entities

- **利用者**: 備品を検索・予約する利用者。管理者ロールを持つ場合は管理機能も利用できる。
- **備品**: 備品名・カテゴリ・管理番号・在庫数を持つ貸出対象。
- **予約**: 利用者・備品・利用期間・状態・予約番号を持つ。
- **貸出**: 予約に基づく貸出日時・返却予定日・返却日時・備品状態を持つ。
- **在庫変更履歴**: 在庫数の変更前後・変更理由・実施者・実施日時を持つ。

## Success Criteria

- **SC-001**: 利用者は検索開始から3分以内に備品予約を完了できる。
- **SC-002**: 在庫数を超える重複予約は0件である。
- **SC-003**: 返却期限超過の通知漏れは0件である。
- **SC-004**【v1対象外・将来】: 月次利用実績を3操作以内でCSV出力できる。

## Assumptions

- 認証基盤とメール通知基盤は既存サービスを利用できる。
- 管理番号は備品ごとに一意である。
- 時刻はシステム共通のタイムゾーンで扱う。

## Out of Scope (v1)

- 月次利用実績のCSV出力（FR-040／SC-004）は将来バージョンで提供する。
- 備品の購入申請および会計処理は対象外とする。
