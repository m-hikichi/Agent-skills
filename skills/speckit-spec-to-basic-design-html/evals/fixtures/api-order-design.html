注文登録

現行

01 注文受付 ／ 01 API受付 ／ 01 登録

外部ECから注文を受け付けて注文IDを発行する

アクター
外部EC
起動契機
外部ECが注文登録APIを呼び出す
実行形態
API
API-001 注文登録API
入力
  • 注文番号
  • 商品明細
  • 配送先
  • 冪等キー
出力
  • 注文ID
  • 受付結果
事前条件
  • 入力必須項目が指定されている
事後状態
  • 注文が受付済みで保存される
業務ルール
  1. 正常な注文を受付済みとして登録し注文IDを返す spec記載 FR-001 AC-001-01
例外・失敗時
  • 入力必須項目が不足する → 注文を作成せず入力エラーを返す 設計導出 FR-001
    導出理由: FR-001で列挙された入力を満たさない要求から完全な注文を作成できないため
対象データ
  • 注文
  • 注文明細
根拠
US-001 AC-001-01 FR-001 SC-001

業務ルール

例外・失敗時

許可された条件に従って注文状態を変更する

アクター
注文管理システム
起動契機
出荷・配送・取消処理が状態変更を要求する
実行形態
イベント
EVT-001 注文状態変更契機
入力
  • 注文ID
  • 変更要求状態
出力
  • 変更後状態
  • 拒否理由
事前条件
  • 対象注文が存在する
事後状態
  • 許可時だけ注文状態が更新される
  • 拒否時は現在状態を維持する
業務ルール
  1. 受付済み・配送中・配送済み・取消の許可条件に従って遷移する spec記載 FR-010
  2. 配送済みから取消への変更を拒否する 確認済み FR-011 EC-001 CL-20260621-02
例外・失敗時
  • 禁止された状態遷移を要求する → 状態を変更せず拒否理由を返す spec記載 FR-011 EC-001
対象データ
  • 注文
  • 注文状態履歴

03 外部連携 ／ 01 状態通知 ／ 01 イベント送信

送信に失敗した状態変更イベントを再送する

アクター
システム
起動契機
再送待ちイベントの実行時刻になる
実行形態
バッチ
BAT-001 イベント再送ワーカー
入力
  • 再送待ちイベント
  • 過去の送信回数
出力
  • 再送結果
  • 更新された送信履歴
事前条件
  • イベント送信が失敗している
事後状態
  • 成功時は再送完了となる
  • 上限到達時は再送を終了する
業務ルール
  1. 送信失敗時は最大3回まで再送する spec記載 FR-021 EC-002
  2. 各再送の日時と結果を履歴へ記録する spec記載 FR-021
例外・失敗時
  • 3回目の再送も失敗する → 再送を終了し最終失敗として記録する 設計導出 FR-021 EC-002
    導出理由: 最大3回までという上限に達した後は追加再送を行えないため
対象データ
  • 状態変更イベント
  • イベント送信履歴

03 外部連携 ／ 02 日次照合 ／ 01 件数照合

外部ECと内部の注文件数を日次で照合する

アクター
運用担当者
起動契機
毎日02:00になる
実行形態
バッチ
BAT-002 日次注文照合
入力
  • 外部ECの対象日注文件数
  • 内部の対象日注文件数
出力
  • 照合結果
  • 不一致通知
事前条件
  • 外部ECの件数取得APIを利用できる
事後状態
  • 照合結果が保存され、不一致時は運用担当者へ通知される
業務ルール
  1. 毎日02:00に外部ECと内部の注文件数を照合する spec記載 FR-030
  2. 件数不一致を運用担当者へ通知する spec記載 FR-030
例外・失敗時
  • 外部ECから件数を取得できない → 照合不能として運用担当者へ通知する 設計導出 FR-030 ASM-002
    導出理由: 外部件数がなければ照合結果を確定できず、FR-030の運用通知が必要になるため
対象データ
  • 注文
  • 日次照合結果
根拠
FR-030 ASM-002
