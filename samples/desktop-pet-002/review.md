## 機能の分け方

3つの User Story をそのまま3機能にするのではなく、少なくとも次の責務で整理するのが妥当である。

| 責務 | 主な要件 |
|---|---|
| 常時待機・自律挙動の停止 | FR-001〜004 |
| ドラッグ中の走行方向・停止・中断 | FR-005〜011、FR-025 |
| サイズメニュー・即時反映 | FR-012〜014、FR-017 |
| サイズの保存復元・旧設定互換・ペット切替 | FR-016、FR-018、FR-021 |
| 足元アンカー・作業領域・DPIと座標変換 | FR-015、FR-022、FR-024 |
| 全サイズの描画・当たり判定・非侵襲性 | FR-019、FR-020 |

FR-023 の状態独立は複数機能にまたがる。さらに実装上の独立検証単位として、座標変換の構造検査や性能測定を分けてもよい。機能数を要件数に一致させる必要はない。

## 入力資料に残る確認事項

1. **走り開始の時間条件**: spec.md 356行目の SC-002 は「動かし始めてから0.3秒以内」。一方で241行目以降の FR-025 は各軸2 DIPに達するまで待機を要求する。非常に遅いドラッグでは両立しないため、時間計測の起点と適用条件を確認する。レビュー担当が勝手に「閾値到達後」と書き換えない。
2. **設定の型不一致時に他の設定を保護するか**: FR-021（spec.md 292行目）は既存設定の保持を要求するが、contracts/app-settings.md 81行目は `scalePercent: "big"` の場合にファイル全体を既定値へ戻す。qa/us3-visual-qa.md 44行目も位置リセットを記録している一方、32行目の CHK036 見出しは「他の設定は保持」。型不一致を保持規則の例外とするか、元仕様で確認する。
3. **OS表示倍率変更時のはみ出し補正**: qa/final-visual-qa.md 25行目の CHK040 は、ScalingChanged時の補正が未定義と明記している。自動的に補正されるという期待結果を追加しない。
4. **既存001から継承する範囲**: spec.md 21行目は上書き対象以外の001要求をすべて維持するとしている。002資料のみで、既存要求すべての追跡性・回帰試験網羅を確認したとは言えない。今回の文書は002変更範囲の資料として扱う。
5. **既存QA記録の検証範囲**: 視覚QAの未チェック項目が31件ある。過去のPASSを新しいテスト仕様の実施済み結果に転記しない。性能記録はMediumのUS1ビルドとX-Largeの最終ビルドであり、全4サイズ・同一最終ビルドの測定証跡ではない。互換性も記録上はgenba-nekoの例であり、全パッケージの実測証明ではない。
