# 品質基準

動画の品質を4つの観点に分ける。Aが通っていることは、B〜Dが良いことの根拠にならない。gateは1つでもfalseなら不合格で、平均点で相殺しない。

## A. 技術的な成立（機械が判定）

| 項目 | 判定する処理 |
|---|---|
| Schema・参照・図の整合（node/segmentのid、強調の範囲） | `project_validate` |
| 音声のhash・尺・VOICEVOX version、scene尺の合計 | `resolve`（lock） |
| 1920×1080・30fps・H.264/AAC・yuv420p、尺とlockの一致、manifest、字幕が尺内、章の順序 | `output_inspect` |

Aは「ファイルが正しく作られた」ことだけを示す。

## B. 視認性

機械が測るもの（数値と根拠）:

| 測定 | 基準 | 根拠 |
|---|---|---|
| 字幕の文字サイズ（`project_lint` `SUBTITLE_SMALL`） | 40px以上 | 1920pxを640pxへ縮小すると1/3になる。40pxで約13px |
| 字幕が枠に収まるか（`SUBTITLE_TOO_LONG`） | 文ごとに分けても行数の上限以内 | 1行の文字数は字幕幅÷文字サイズで算出 |
| カード下の空白率（storyboardの`layoutMetrics`） | 0.3以下 | 描画した絵コンテの画素から実測。改修前のサンプルで「半分空いている」と指摘されたページは0.33〜0.45だった |
| コードの文字サイズ（`CODE_TEXT_SMALL`） | 32px以上 | 全画面のcodeは行の長さと行数から自動で決まる。32pxは640px表示で約11px |
| 図のラベルの長さ（`DIAGRAM_LABEL_LONG`） | nodeの間隔に収まる | 間隔÷文字サイズで文字数の上限を算出 |
| 非選択要素の濃さ | 不透明度0.75（deck）／0.72（その他） | 白地に標準の本文色で4.5:1以上を保つ値 |
| ページの表示時間 | 10秒未満は警告（deckのみ、表紙を除く） | 資料型の目安は20〜40秒。短い操作手順などdeck以外には当てはめない |

reviewerが見て判断するgate:

- `noOverflowOrClipping` / `noUnintendedOverlap` / `safeMargins` / `readableContrast` / `subtitleReadable` / `consistentTypography` / `thumbnailReadable`
- `readableWhenScaledDown`: 完成動画の640×360の個別フレーム（storyboard段階では画像を縮小して）で、主役の文字と字幕が読める。補助情報（フッター、注記）は対象外
- `balancedLayout`: 主役に見合う面積がある。大きな空白と小さな文字が同居していない。背景に欠けや意図しない帯がない

## C. 説明としての品質

- `visualMatchesContent`: 画面が台詞・字幕と矛盾しない。強調は読んでいる対象と一致し、先読みしない
- `claimsAccurate`: 正確さ（下記）。原典やコードが渡された場合は照合する
- `fitsAudience`: `brief`の視聴者・疑問・到達点に合っている
  - 冒頭のタイトル画面で、何の動画か（題名と、誰向けか・何が分かるか）が示されている。説明から唐突に始まっていない（30秒未満の動画と、利用者が省くよう指定した場合を除く）
  - 見る理由（完成像・具体例・困りごと）が早い段階にある
  - 用語が、必要になる場面より前に列挙されていない
  - 「何か」だけでなく「なぜ」「どう働くか」がある
  - 本編の範囲が`inScope`に収まり、網羅のために論点が増えていない
  - 画面の文章・ポイント欄・字幕が同じ文の繰り返しになっていない

### 正確さ

- 主体の役割、通信方式、生成物を取り違えていない（誰が呼び、誰が応え、何が渡るか）
- 短い要約が、別の意味に読めない
- 「必ず」「ずれない」「同じになる」などの言い切りに、成立条件（端数処理、余韻時間、版、例外）が添えられているか、条件なしで成り立つ
- 製品固有の仕様を、一般的な定義として述べていない
- 数式・例の数値が、実装の条件と一致する

## D. 映像としての品質

- `formFitsMeaning`: 意味と形式が合っている（`visual-guidelines.md`の「意味と形式の対応」）。包含を横並びで、時間を表で、受け渡しを箇条書きで示していない
- `clearFocus`: 各場面で見る場所が1つに決まる。強調が色だけでなく枠・太さ・位置でも分かる
- `variedPresentation`: 同じ形式の画面と強調の切替だけが続いていない。動きが順序・因果・対応・変化を伝えている。意味のないズーム・点滅・効果音で代用していない。短い動画や意図して一様な動画では`not_applicable`にでき、理由を`notApplicableReasons`に書く

これらは形式の点検ではない。「実例がある」「動きがある」こと自体を合格の条件にしない。視聴者の理解に効いているかを、場面と根拠を挙げて判断する。

## 指摘の書き方

指摘は修正につながる形で書く（`review.json` schemaVersion 2.0.0）。

| 項目 | 内容 |
|---|---|
| `sceneId` または `timeSeconds` | 対象の場面または時刻 |
| `gate` | 関係するgate |
| `problem` | 何が、どこで、どうなっているか |
| `impact` | 視聴者にとって何が困るか |
| `evidence` | 根拠（画像のパス、実測値、台詞の引用、原典の該当箇所） |
| `fix` | JSON Pointerと変更後の姿。構成の問題は`scenePlan`のどこをどう変えるか |
| `recheck` | 次のiterationで確認した結果（初回は省略） |

- `error`: gateがfalseになる問題。1件でもあれば`fail`
- `warning`: 修正する価値があるが、gateは成立している問題。好みだけの指摘は書かない
- 主観的な判断ほど、場面と根拠を具体的に書く。「分かりにくい」だけの指摘は無効

## 完成動画で確認できること・できないこと

`output_review_frames`が出すのは静止フレームである。

| 確認できる | 確認できない |
|---|---|
| 各場面の冒頭・中央・末尾の状態、ページ切替直後に読める状態か、字幕切替の前後、動きの途中の位置、640px縮小での可読性 | 動きの滑らかさ・速さの体感、フレーム間のちらつき、音声の読み・音量・語尾の切れ・間、音声と画面の体感上の一致 |

確認できない項目は、聴取・視聴した場合だけ「確認済み」と報告する。それ以外は「未確認」と明記する。
