# Visual選択ガイド

visualは、場面の設計（`request.json`の`scenePlan`: 何を伝え、何を見せ、どこを見せるか）を決めてから選ぶ。先にテンプレートを決めて文章を流し込まない。

## 意味と形式の対応

説明している関係を、その関係の形で見せる。

| 説明する内容 | 形式 | 使うvisual |
|---|---|---|
| 手順・流れ（順番に進む） | 工程図 | `flow`（1工程ずつ進む）、`slide`の`steps` |
| 通信・受け渡し（誰から誰へ何が渡るか） | 接続図とデータの移動 | `diagram`（`active.packet`で渡るものを動かす） |
| 包含関係（AがBを含む） | 入れ子の図 | `nest`、`diagram`の`groups` |
| 時間・同期（同時、前後、長さ） | 同じ時間軸に並べる | `timeline`（`cursor`で現在位置） |
| 比較 | 左右対比、比較表 | `split`、`table` |
| 変化 | 変更前と変更後 | `split`、`code`の`diff`、同じページの強調切替 |
| コードや設定 | 短い実物と結果の対応 | `code`（`highlightLines`）、`slide`の`code`ブロック＋結果 |
| 失敗と修正 | 問題箇所と改善後の対比 | `split`、`code`の`diff` |
| 並列の項目 | 一覧 | `bullets`、`slide`の`cards`・`list` |
| 1つの数値・定義 | 大きく1つ | `metric`、`statement`、`slide`の`kpis` |

避ける組み合わせ:

- 包含を横並びのカードで示す（同格に見える）→ `nest`
- 時間の前後・重なりを表で示す（長さと同時性が見えない）→ `timeline`
- 受け渡しを箇条書きで示す（向きと中身が見えない）→ `diagram`
- 全ページをカードと表にする（`project_lint`の`NO_RELATIONAL_VISUAL`）。並列の列挙だけの動画ならそれでよい

テンプレートの種類を増やすこと自体は目的にしない。1つの図を数sceneにわたって保ち、強調と動きで説明を進めるほうが、場面ごとに別の画面へ切り替えるより理解しやすい。

## 共通上限

- 1 sceneは1メッセージ。
- 画面タイトルは100文字以下だが、実運用は日本語28文字程度を目安にする。
- 字幕は40px以上、最大2行。1行に収まらない台詞は文の切れ目で分割され、音声に合わせて順に表示される。1文が2行を超える台詞は、読点で区切るかsceneを分ける。
- bulletsは最大5件。推奨3件、各項目は1〜2行。
- codeは表示可能な行だけを入れる。全ファイルを貼らない。
- `assetId`は`assets[]`に存在し、期待するtypeと一致させる。

## visualの使い分け

| type | 用途 | 必須項目 | 避けること |
|---|---|---|---|
| `title` | 導入、章扉、1つの結論 | `title` | 長い説明文 |
| `bullets` | 3〜5点の列挙 | `items` | 段落や入れ子 |
| `split` | 2案、Before/Afterの比較 | `left`, `right` | 3列以上の比較 |
| `media` | ローカル画像・動画 | `assetId` | URLやSVG |
| `code` | source、diff、terminal | `variant`, `code` | 小さすぎる全文表示 |
| `quote` | 短い引用・要点 | `quote` | 出典の捏造 |
| `metric` | 数値、棒、折れ線 | `variant`, `label` | 根拠のない数値 |
| `outro` | まとめ、次の行動 | `title` | 新しい論点 |
| `flow` | 入力から結果までの工程を動きで説明 | `steps`, `activeStep` | 無関係な移動、全工程を一度に説明 |
| `table` | 一覧表・料金表・条件表。読み上げ中の行/列を強調 | `columns`, `rows` | 6行・5列を超える表、1セルに長文 |
| `statement` | 番号の要らない1つの文・定義・ルール | `text` | 箇条書きにすべき複数の論点 |
| `slide` | 社内資料のような1ページ。見出しタグ＋タイトルと、最大6ブロック（text・callout・table・cards・kpis・list・steps・code）を12列グリッドに配置する | `title`, `blocks` | 1ページ1要素だけの細切れのページ、カードからはみ出す量 |
| `diagram` | 接続と受け渡し。2〜5個のnodeを横に並べ、`links`で結ぶ。`groups`は隣り合うnodeを囲む枠（「同じ場所で動く」など）。`active`でnode・linkを強調し、`active.packet`でラベル付きの荷物をlink上で移動させる | `nodes`, `links` | 6個以上の要素、交差する多数の線、nodeに長文 |
| `nest` | 包含関係。外枠の中に最大4個、その中にさらに最大4個の箱。`highlight`にidを指定 | `root` | 包含でない並列の項目、4階層以上 |
| `timeline` | 時間と同期。1〜4本のトラックを同じ時間軸に並べる。`highlight`にsegmentのid、`cursor`に現在位置 | `end`, `tracks` | 時間に関係しない一覧、8個を超えるsegment |

`metric:number`は`value`だけを使う。`metric:bar|line`は`values`を使い、`labels`を指定する場合は同じ要素数にする。

`flow`は2〜4工程。隣接sceneで同じ`steps`を維持し、`activeStep`を0→1→2のように進める。音声は現在の工程の入力・処理・結果を説明する。1秒のデータ移動後に到着先を強調するので、短すぎるsceneを避ける。移動の途中、到着後、scene境界を完成MP4から確認する。登場fadeだけを「動きによる説明」と数えない。

### diagram

- nodeは左から右へ、説明の順序どおりに並べる。隣り合うnode同士のlinkは直線の矢印、離れたnode同士は上を回る弧になる。同じ2つのnodeを結ぶlinkは上下に並ぶ（往復の表現に使う）。
- linkのラベルは渡るものの名前にする（8文字程度まで）。nodeが4個以上で間隔が狭いときは、ラベルがnodeの下に並ぶ。
- packetはscene開始と同時に動き出す（字幕cueの切替には合わせない）。前置きの一文（「注意が1つあります」など）を同じsceneに入れると、説明より先に動きが終わる。動きを説明する文でsceneを始める。
- 1つのsceneで動かすpacketは1つ。「AがBへ頼む」「BがAへ返す」は別のsceneにし、`packet.link`を変える。戻りは、逆向きのlinkを別に定義するか`reverse: true`を使う。packetはscene開始から約1秒で到着する。
- `groups`のnodeは隣り合っていなければならない。`active.groups`にgroupのidを入れると、その枠が強調される（「Dockerの中で動く」のように、枠そのものを説明する場面で使う）。
- linkのラベルは、隣のnodeとの間隔に収まれば矢印の横、収まらなければnodeの下に並ぶ。矢印の横に置くほうが対応が分かりやすいので、短くする。
- 隣接sceneで`nodes`・`links`・`groups`を同一に保つと、図はそのままで`active`だけが切り替わる。

### nest

- 外側から内側へ説明する順に`highlight`を移す。箱の中の箱が「含まれる」ことを示すので、同格のものを入れ子にしない。
- `detail`は箱のラベルの横に出る短い補足（20文字程度まで）。

### timeline

- `end`と各segmentの`start`/`end`は同じ単位の数値。`unit`は目盛りに付ける文字（「秒」「分」「枚」など）。
- `ticks`を省くとsegmentの境界が目盛りになる。
- 同じ時刻に起きることを別トラックの同じ位置に置くと、同期が見える。`cursor`を隣接sceneで進めると、位置の線が移動する。
- segmentのラベルは幅に収まる長さにする（はみ出した分は隠れる）。

### code

- `highlightLines`（1始まり）で、台詞が説明している行を強調する。隣接sceneで`code`を同一に保てば、コードはそのままで強調行だけが移る。
- 実物は短く切り出す（10行程度まで）。結果と並べるときは`slide`の`code`ブロックと`kpis`/`cards`を同じページに置く。
- 全画面の`code`は、最も長い行と行数に合わせて文字サイズが決まる（最大46px）。32px未満になるほど長いコードは`project_lint`の`CODE_TEXT_SMALL`で指摘されるので、説明している行だけを切り出す。
- diagramの矢印のラベルが隣のnodeとの間隔に収まらないと`DIAGRAM_LABEL_LONG`で指摘される。ラベルは渡るものの名前だけにし、状態はnoteかnodeのdetailに書く。荷物（packet）は矢印の途中で止まり、受け取り側のnodeとラベルを隠さない。

## 同じ画面の連続と強調

- 隣接sceneのvisualが強調指定（`highlight`・`highlightRows`/`highlightColumns`・`emphasis`・`highlightLines`・`active`・`cursor`）以外で一致する場合、画面は再フェード・再入場せず、強調だけが約0.27秒で切り替わる。同じ表や図を説明し続ける場面は、visualを同一に保ち、強調だけを変える。
- 強調されていない要素は読める濃さのまま残る（不透明度0.75前後）。強調は枠・背景・太さで示される。
- ページが変わるとき、前のページは最後のフレームまでそのまま表示され、次のページは5フレーム（約0.17秒）で現れる。フェードアウトは動画の最後だけに入る。
- 強調の切替だけが6回を超えて続くページは、論点の切れ目で分けるか、途中に図や実例を挟む（`project_lint`の`LONG_EMPHASIS_RUN`）。
- 1つの文を「1」「2」の項目に分けない。番号付きbulletsは並列の複数論点だけに使い、1文は`statement`にする。
- 読み上げている行・列・項目を強調し、台詞と画面の対応を取る。
- statementの`emphasis`は、そのsceneの台詞で読み上げる語句だけにする。まだ読んでいない語句を先に強調しない。
- statement・split・bulletsの日本語本文は文節単位で折り返す。意図した位置で改行したい場合は、splitの本文に`\n`を入れる。

## 資料型レイアウト（theme.frame）

解説・研修・規程説明のような「資料を読ませる」動画は、資料型レイアウトを既定にする。

- `theme.frame.style: "deck"`で、グラデーション背景・白いカード・フッター（ロゴ、フッター文言、ページ番号）・下部の章チップ・最下端の進捗線を描く。進捗表示は動画サイトのUIと同じく画面下に置く。`title`・`outro`は表紙レイアウトになり、グラデーションが画面全体を覆う。表紙下部の白い帯はロゴ（`coverLogoAssetId`）を置くための領域で、ロゴを指定したときだけ描かれる。
- `theme.frame.footer`でフッターの量を選ぶ。`full`（既定）は全部、`progress`は進捗線だけ、`none`は何も描かない。章が2つ以下、ページ番号が要らない、短い動画では`progress`にする。空いた分はカードと字幕に使われる。
- `diagram`・`nest`・`timeline`は、deckでは白いカードの上に資料と同じ見出し（`tag`・`title`）付きで描かれる。
- 色は`theme.frame.palette`（`gradientStart`・`gradientEnd`・`primary`・`dark`・`light`・`text`・`marker`）で指定する。省略時は中立色。プラグインには特定の会社・ブランドのデザインを含めない。利用者の会社テンプレートや見本資料がある場合は、その配色・ロゴを**作業プロジェクト側**の`palette`と`assets`に置く。
- ロゴは`assets`に`image`として登録し（権利情報を記録）、`frame`のID（`footerLogoAssetId`・`coverLogoAssetId`・`coverMarkAssetId`）で参照する。`footerText`・`coverCaption`も作業プロジェクト側で指定する。
- 文字が背景に沈まないよう、`theme.foregroundColor`は白などの明るい色にする（サムネイルの文字色にも使われる）。

### ページ設計（ページ遷移を減らす）

- 内容は`slide`で組み立てる。1ページに関連する本文・表・カード・数値・補足をまとめ、ページ内ではsceneごとに強調（`emphasis`・`highlight`・`highlightRows`/`highlightColumns`）だけを動かす。隣接sceneのvisualが強調以外同一なら、画面は静止したまま強調だけが切り替わる。
- 1ページの表示は**20〜40秒**を目安にする。10秒未満のページはstoryboardで警告される。1〜2文しか話さないページは、前後の関連ページと統合する。
- 章の頭で章名だけを言う短いsceneは、その章の最初の内容ページに含める（専用ページを作らない）。
- 余白が大きいページは、次の順で直す。storyboardの`layoutMetrics.blankBottomRatio`が0.3を超えると警告される。
  1. 内容が図にできるなら図にする（`diagram`・`nest`・`timeline`）
  2. `slide.scale`を`large`（1.2倍）または`xlarge`（1.4倍）にし、`align: "center"`で中央に置く
  3. 関連する内容を統合する
- 補足（`callout`の「ポイント」）は余白を埋めるために足さない。足す場合は原典の言い換えに限り、新しい事実を加えない。台詞と同じ文のポイント欄は、字幕と合わせて同じ文が三重になる（`TEXT_REPEATS_NARRATION`）。

### 情報の優先順位

- 1ページの主役は1つ。主役のブロックに広い`span`を与え、補助は狭くするか省く。
- 画面の文字は、図のラベル・数値・短い語にする。文章での説明はナレーションに任せる。
- 文字量が多くて収まらないときは、文字を小さくせず、短くする・ページを分ける・形式を変える。

### ブロックの選び方

| ブロック | 用途 | 目安 |
|---|---|---|
| `text` | 条文・定義などの原文。`label`に条番号 | 原文どおりに引用し、要約しない |
| `table` | 金額表・条件表。読み上げ中の行/列を強調 | 6行×5列まで。行ラベルは短く |
| `cards` | 原則/例外、対比、まとめの要点 | 2〜4枚。本文は2〜4行 |
| `kpis` | 期限・回数・距離など一目で伝える数値 | 1〜4個。値は短く |
| `list` | 並列の項目（伝える内容など） | 1文を分割しない |
| `steps` | 手順・章立て。`numbering`は`number`（既定、1 2 3）・`chapter`（第1章…）・`none` | 2〜6個。4個までは1行に並ぶ |
| `code` | 短いコード・設定の実物。`highlightLines`で行を強調 | 10行程度まで。結果のブロックと並べる |
| `callout` | 注意・条件。台詞の写しにしない | 1〜2行 |

### 文字配置と改行

- 本文は文節単位で自動改行される。書式名・条番号・金額など**分けたくない語**が行をまたぐ場合だけ、その語の前で明示改行（`\n`）を入れる。狭い枠に多くの明示改行を入れると1語だけの行ができるので、storyboardで必ず確認する。
- 1つの文を番号付きの項目に分けない。字幕（`subtitle`）は要約せず台詞の全文を出す（2行に収まる長さにsceneを分ける）。

## 全体像（navigation）

- 3分を超える解説では、プロジェクト直下の`navigation.groups`（2〜6章、各章タイトルは8文字程度まで）で章の進捗を常時表示する（`deck`ではフッター中央、それ以外では画面上部）。各groupは`sectionIds`で連続するsectionを束ねる。どのgroupにも属さないsection（導入など）では、現在の章は強調されない。
- 冒頭で全体の流れを示し、各章の頭で現在地を言葉でも伝える。

## テンプレート追加境界

JSONから任意React componentを読み込めない。既存の固定visual（15種類）のテキスト・色・asset・variant・強調で表現する。さらにtypeが必要な場合は、Schema・型・renderer・goldenテスト・ドキュメントを同時に更新する開発作業として扱う。
